### Brief
Your project's one-page constitution: purpose, users, principles, limits.

### Checkpoint
A moment where you decide: the mockups, the summary, the go.

### Correction round
The implementer fixes open findings, then the same reviewers re-check. Three at most.

### Decision card
A question, its options, a firm recommendation and the cost if wrong.

### Decisions made for you
What the team decided without asking, each with its cost if wrong.

### Dry run
The architect runs a risky task's code in a scratch copy while planning, to prove the plan.

### Feature
One capability on one branch, with three checkpoints.

### File limit for a fix
The most files a Fix may change, 3 by default.

### Final review
One last review of the whole branch against the spec and the plan, once every task is done.

### Fix
A change of at most 3 files with no schema or sign-in change.

### Logbook
`.gtm/ledger.md`: one line per lesson, ruling or deferred finding, kept across changes.

### Milestone
Work across several branches, each run as a Feature.

### Mockups
One page showing each new screen in light and dark, scored by the critic.

### Spec
The document the architect writes before any code: what will be built, what is left out, and
how each part is checked.

### Summary
The ten lines at the top of a spec, written for you.

### Team settings
Which roles run, how hard each one thinks, and why.
