# Documentation guideline

> When to read: architect (what a feature must document), reviewer and final reviewer when docs change.

- **Where:** README = what it is, install, quick start, links; `docs/` = how it works and why;
  code comments = why, never what; CHANGELOG = what changed per release. <Project map.>
- **Every doc starts with a 3-5 line summary**; one idea per section; tables over long lists.
- **Tone:** plain, factual, no hype; the reader's language; examples over adjectives.
- **Done means documented:** a user-visible change updates its doc in the same branch.
- **Emoji:** none in docs, specs, plans or ledgers; the README may use a few where they help scanning.
